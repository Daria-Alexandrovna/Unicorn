## Что здесь

Проект собирает и анализирует данные учебной базы ПРАЙМ.

В ДЗ-1 проведён базовый анализ операций: рассчитаны количество и сумма успешных операций, активность участников, показатели по дням недели и дополнительные проверки данных.

В ДЗ-2 собрана клиентская витрина на индивидуальном сегменте с зерном «одна строка — один клиент». В витрину объединены данные о клиентах, подписках, успешных платежах и участии в подписках. При сборке контролируются кратности соединений, потери ключей и независимые проверки ЗЕРНО / ДЕНЬГИ / ЛЮДИ.

Дополнительно в ДЗ-2 рассчитаны ARPPU, CAC, показатели по тарифам, каналам и регионам, а также исследовано влияние повышения цены на выручку и отток клиентов.

## Как запустить

Нужны [Git](https://git-scm.com/) и [uv](https://docs.astral.sh/uv/).
Python отдельно ставить не нужно — его поставит `uv`.

```bash
git clone git@github.com:Daria-Alexandrovna/Unicorn.git
cd Unicorn
uv sync
```

Доступ к учебной базе выдаёт бот курса по команде `/db`.
Полученную строку подключения нужно положить в `.env`:

```bash
cp .env.example .env
```

После этого в `.env` нужно вставить строку подключения из бота.

Проверка подключения:

```bash
uv run python -c "from prime.config import get_engine; print(get_engine().connect().execute(__import__('sqlalchemy').text('select current_user')).scalar())"
```

Запуск JupyterLab:

```bash
uv run jupyter lab
```

Основные ноутбуки проекта:

- `notebooks/hw1.ipynb` — ДЗ-1;
- `notebooks/hw2.ipynb` — ДЗ-2;
- `notebooks/С3-аудит-сырых-данных.ipynb` — семинар 3;
- `notebooks/С4-витрина-клиента.ipynb` — семинар 4.

## Что здесь считается

### ДЗ-1

- **Успешные операции** — операции, для которых признак успешности равен `True`.
- **Сумма успешных операций** — сумма значений только по успешным операциям.
- **Активность участника** — количество его успешных операций.
- **Показатели по дням недели** — суммы операций с группировкой по дню недели.
- Дополнительно проверяются распределения операций, активность участников и устойчивость результатов на выборках.

### ДЗ-2

- **Выручка** — сумма платежей со статусом `success`. Возвраты `refunded` повторно из неё не вычитаются, потому что они изначально не входят в этот расчёт.
- **Платящий клиент** — владелец подписки, у которого есть хотя бы один успешный платёж.
- **ARPPU** — выручка / количество платящих клиентов.
- **`n_payments`** — число успешных платежей клиента.
- **`paid`** — сумма успешных платежей клиента.
- **`n_memberships`** — количество подписок, в которых клиент участвует как участник.
- **`uses_prime`** — клиент либо владеет подпиской, либо участвует хотя бы в одной подписке.
- **Историческая цена тарифа** определяется по дате платежа и интервалу действия соответствующей цены.
- **CAC** — расходы на привлечение / количество новых клиентов для соответствующих канала и месяца.
- **Выручка по каналам и регионам** считается по каналу привлечения владельца подписки.
- При `groupby` пропуски в канале учитываются отдельно, если это необходимо для сохранения контрольной суммы.

Для итоговой клиентской витрины используются три независимых контроля:

- **ЗЕРНО** — одна строка должна соответствовать одному клиенту сегмента;
- **ДЕНЬГИ** — сумма `paid` в витрине должна совпадать с независимой суммой успешных платежей;
- **ЛЮДИ** — число клиентов с `uses_prime = True` должно совпадать с независимым расчётом по владельцам и участникам подписок.

В исследовательской части ДЗ-2 отдельно рассматриваются:

- эффект повышения цены на выручку с разделением эффекта цены и изменения объёма;
- изменение оттока до и после повышения цены;
- доля отмен с причиной `too_expensive`.
